# 版式与迭代方法

## 不同叙事用途选择不同布局

| 内容 | 可选布局 | 重点 |
| --- | --- | --- |
| 总体技术路线 | 架构层次、三方协作、输入—处理—输出 | 将技术连接到设计目标，避免技术名词堆积 |
| 模型原理 | 前向流程、训练反馈环、模块示意 | 箭头符合真实机制，区分训练与推理 |
| 训练与部署 | 单张结果图 + 分组技术说明 + 输出标签 | 解释数据、训练、推理、业务调用的衔接 |
| 智能体协作 | 中央真实界面 + 两侧职责，或工作流主图 | 区分语义生成、任务编排与人工复核 |

这些是选择示例，不要求每份稿件都出现全部布局，也不要让所有页面套用同一张模板。

## 用模板小元素改善文字

- 阶段标题条：承载“数据准备、模型训练、服务输出”等短标题；下方保留一行说明，不在标题条里塞满句子。
- 圆形或线性图标：区分训练、推理、存储、审核等职责，与对应标题基线对齐，不将图标当作额外主图。
- 输入标签：将不同来源拆为“影像数据：类别 / 坐标 / 置信度”“病历信息：病史 / 症状”等，不让它们淹没在段落中。
- 输出分组：将长列表分为“类别与位置、置信度、标注图”等并列小组，用大小和颜色区分标签与解释。
- 图片角框：与模板一致时可用于聚焦真实结果图，不叠加多层发光边框。

优先使用当前模板已有素材；不因这些示例强行添加科技风装饰。

## 删除图片后重排

1. 明确剩下图片负责证明什么，裁切聚焦，并保持比例。
2. 合并相近说明，去掉重复标题或段落。
3. 用腾出的区域解释实现方法、职责边界或输入输出，而不是补充空泛价值口号。
4. 重新分配图与文的宽度，统一行距、分组间距及左右对齐。
5. 检查整页是否仍有明确阅读顺序，不要求每块区域都被填满。

例如，原本两组截图可改为“一张检测结果图 + 训练优化说明 + 推理接口与输出”，而不是删掉一组后留下空洞。

## 用户评价“AI 味重”时

先判断具体原因：重复卡片、机械对称、空泛大标题、照片过小、没有主次，还是偏离原模板。保持已认可的视觉方向进行局部修正；不要自动换成白底、删掉全部装饰或改用另一套无关模板。

## 技术真实性

模型训练的示例闭环可以包含样本输入、特征提取、预测、损失计算、反向传播与参数更新；部署推理只执行相应前向计算。闭环图不能暗示系统在每次使用时都会自动更新模型。

对于报告或建议生成，明确草稿、人工复核和发布的角色；不要把技术示意冒充已验证性能，也不要从参考截图臆造新能力。
